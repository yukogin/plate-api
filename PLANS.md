## Работа с документацией

- AGENTS.md — постоянные правила, стек, команды и соглашения. Создать на этапе 1, команды записывать после их появления в проекте.
- docs/specs/*.md — требования и критерии готовности отдельных этапов.
- PLANS.md — порядок работы, статус и краткие сведения о выполнении.
- docs/adr/*.md — принятые архитектурные решения и их причины. Создавать вместе с соответствующим решением.
- README.md — фактическая инструкция запуска и использования. Дополнять после каждого этапа.

Требования к API определяет backend-api.md; схема и инфраструктура описаны в architecture-and-database.md, доступ — в authentication.md. Остальные документы ссылаются на эти источники, чтобы не копировать требования.

## Как запускать этап в Codex

Пример первого запроса:

> Прочитай AGENTS.md, если он существует, PLANS.md и docs/specs/architecture-and-database.md. Реализуй только этап 1. Учитывай общую модель продукта из docs/specs/backend-api.md. В конце обнови статус этапа, перечисли изменения, выполненные проверки и ограничения.

Для следующего этапа указать его номер и файл ТЗ. Завершать этап после выполнения его критериев; не переходить автоматически к следующему. Внешний деплой не входит в эти задачи.

## Завершение этапа

Обновить статус и кратко записать результат. Отделять выполненные проверки от запланированных; непроверенное поведение не объявлять работающим. При блокировке указать причину и следующий шаг.

Автоматические тесты добавлять и запускать по отдельному запросу пользователя. Для каждого этапа подготовить воспроизводимые команды ручной проверки. Сборку и проверку типов можно выполнять.

## Результат этапа 1

- Созданы `AGENTS.md`, `README.md`, ADR 0001, каркас NestJS, конфигурация, модули `prisma`, `health`, `auth` и `recipes` (последние два пока без маршрутов).
- Добавлены Prisma-схема и сохранённая миграция `Recipe`, `User`, `Role`, Docker Compose с постоянным volume, пример окружения и lock-файл npm.
- Выполнено: `npm run db:generate`, `npm run db:migrate` на пустом локальном PostgreSQL, проверка таблиц через `psql`, `npm run typecheck`, `npm run build`, `docker compose config --quiet`.
- Ручные HTTP-проверки: `GET /api/v1/health` вернул 200 при доступной базе и 503 при остановленном контейнере; `/api/docs` вернул 200. Контейнер после проверки снова запущен.
- `npm audit --omit=dev` после обновления транзитивных зависимостей: 0 уязвимостей. Автоматические тесты не добавлялись и не запускались согласно правилу плана.
- Ограничения: вход, seed администратора и CRUD рецептов относятся к следующим этапам. Локальный Git-репозиторий и `origin` добавлены после завершения этапа 1; доступ к GitHub по SSH пока не подтверждён (`Permission denied (publickey)`).
