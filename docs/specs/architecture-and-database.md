# Этап 1. Архитектура и база данных

Статус: готово к реализации.
Зависимости: отсутствуют.
Общий контракт продукта: [Backend API](backend-api.md).

## Цель

Подготовить запускаемый каркас модульного монолита и PostgreSQL-схему для приложения «Рецепты». На этом этапе не реализовывать вход и CRUD рецептов.

## Стек

Node.js LTS, TypeScript в strict-режиме, NestJS, PostgreSQL, Prisma ORM, class-validator, class-transformer, Swagger/OpenAPI.

Выбрать совместимые стабильные версии на момент реализации и зафиксировать их lock-файлом. Зафиксировать версию Node.js. При наличии проекта использовать принятый package manager; для нового проекта — npm.

Prisma выбрана за явную схему, миграции и типизированные запросы. TypeORM одновременно не подключать.

## Архитектура

Controller → Service → Repository → Prisma/PostgreSQL.

- Controller принимает HTTP-запросы и DTO.
- Service содержит правила приложения.
- Repository инкапсулирует запросы к базе.
- Prisma-модуль управляет подключением и отключением клиента.
- Контроллеры не обращаются к Prisma напрямую.
- Модули: recipes, auth, prisma, health; общий код размещать в common только при необходимости.
- Не вводить микросервисы, CQRS, очереди, кеш или универсальный базовый репозиторий.

## Схема данных

### Recipe

| Поле | Тип | Условия |
| --- | --- | --- |
| id | UUID | Первичный ключ |
| title | string | Обязательное |
| description | string / null | Необязательное |
| ingredients | string[] | Обязательный упорядоченный массив |
| steps | string[] | Обязательный упорядоченный массив |
| prepTimeMinutes | integer / null | Необязательное |
| servings | integer / null | Необязательное |
| imageUrl | string / null | Необязательное |
| createdAt | timestamp | Заполняется при создании |
| updatedAt | timestamp | Обновляется при изменении |

### User

| Поле | Тип | Условия |
| --- | --- | --- |
| id | UUID | Первичный ключ |
| email | string | Уникальный; trim + lowercase перед сохранением и поиском |
| passwordHash | string | Только хеш |
| role | enum admin, user | По умолчанию user |
| createdAt | timestamp | Заполняется при создании |
| updatedAt | timestamp | Обновляется при изменении |

Даты хранить с учётом часового пояса; API отдаёт ISO 8601 в UTC.
Ингредиенты и шаги хранятся PostgreSQL-массивами строк; отдельные таблицы и загрузка изображений в MVP не нужны.
Проверки обязательности строк и содержимого массивов реализуются в DTO на этапе 3.

## Конфигурация и инфраструктура

- Добавить миграцию создания схемы; хранить миграции в репозитории. Не заменять миграции автоматической синхронизацией схемы.
- Добавить Docker Compose для PostgreSQL с постоянным volume и healthcheck.
- Добавить .env.example: NODE_ENV, PORT, DATABASE_URL, JWT_SECRET, JWT_EXPIRES_IN, ADMIN_EMAIL, ADMIN_PASSWORD, при необходимости CORS_ORIGINS.
- Не включать настоящие секреты; .env исключить из Git.
- Проверять обязательные настройки и завершать запуск с понятной ошибкой при неверной конфигурации.
- Подключить глобальный ValidationPipe: transform, whitelist, forbidNonWhitelisted.
- Установить общий API-префикс /api/v1.
- Подготовить Swagger UI по /api/docs; описание DTO дополняется на следующих этапах.
- Добавить публичный GET /api/v1/health: 200 при доступной базе, 503 при недоступной. Не выдавать параметры подключения.
- CORS по умолчанию выключен; при настройке разрешать только заданные origin. Нативному iOS-клиенту CORS не требуется.
- Поддержать корректное завершение приложения и отключение от базы.

## Критерии готовности

1. Зависимости установлены и зафиксированы lock-файлом.
2. Приложение собирается и запускается.
3. PostgreSQL запускается через Docker Compose.
4. Миграции применяются к пустой базе и создают Recipe, User и enum ролей.
5. Prisma Client генерируется.
6. Health проверяет подключение к базе; Swagger открывается.
7. В репозитории нет настоящих секретов.
8. Документация содержит воспроизводимые команды.

Seed администратора реализуется на этапе 2 вместе с хешированием пароля. Подготовить ручную проверку; автоматические тесты — по отдельному запросу.
